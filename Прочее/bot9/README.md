# bot9 — бот группы для ВКонтакте

Версия по [задаче #21](https://github.com/PavelChurkin/ai_mind_test1/issues/21), на базе [bot8](../bot8/README.md). Нового две вещи: база знаний с иерархическими пересказами `/раг2` и название группы из `.env`. `rag.py` и `/раг` работают как раньше; сохранены команды bot8, рассуждения, роли, склейка длинных сообщений, картинки, паузы, лимиты, пересказы, `/мысль`, серверный запуск и Ansible. Старые папки ботов остаются самостоятельными версиями.

## Название группы

Название задаётся в `.env`:

```dotenv
GROUP_NAME=грань
```

Ниже в тексте «Имя» — это значение `GROUP_NAME` с заглавной буквы, сейчас «Грань». Переменная определяет слово, на которое откликается бот, и команды с обращением («Имя, стоп машина», «Имя, запомни», «Имя, РАГ вопрос», «Имя, перескажи»), имя в роли, запросах к модели, справке и консоли, описание службы Ansible. Регистр и лишние пробелы не важны, название может состоять из нескольких слов; пустое или отсутствующее значение означает `грань`. После изменения перезапустите бота.

- Идентификаторы `gran` в коде, файлах и службе (`gran9.db`, `gran-bot9`, логгер) оставлены как есть.
- Бот откликается только на название в той форме, как оно записано; склонения обращением не считаются, как и раньше с «Гранью».
- Подстановка `{GROUP_NAME}` работает и в своей `Роль.txt`. Если перенесли старую роль с написанным в ней именем, она останется дословной — поменяйте её сами. То же относится к ролям бесед, сохранённым `/роль`.
- `BOT_NAME` теперь равно названию группы: прежнее значение по умолчанию «Грань разумного» сменилось на «Грань». Этим именем подписаны реплики бота в истории, которую видит модель.

## База знаний с пересказами: /раг2

`/раг2` — улучшенная версия `/раг` по схеме Parent-Child / Summary Retrieval. Индексы и папки у них разные, команды устроены одинаково.

| Команда | Результат |
|---|---|
| `/раг2 вкл` | Каждый ответ сначала ищется в индексе 2: нашлось — ответ только по фрагментам, нет — пометка «Поиск по базе знаний не дал результата.» и обычный ответ |
| `/раг2 выкл` | Выключить этот режим |
| `/раг2 вопрос` или «Имя, РАГ2 вопрос» | Разовый строгий вопрос к индексу 2, с источниками; не нашлось — «В базе знаний ничего не нашлось.» |
| `/раг2` | Книги, сколько фрагментов уже с пересказом, сколько в очереди, последняя ошибка |

**Как это работает.** Положите книги (те же форматы, что и в `RAG`) в папку `RAG2` рядом с ботом. При запуске и при каждом вопросе бот замечает изменения файлов и режет текст на фрагменты по 2000 символов с перекрытием 200 (`RAG2_CHUNK_CHARS`, `RAG2_CHUNK_OVERLAP`). Фоновый поток отправляет каждый фрагмент модели `MODEL_NAME` с просьбой о пересказе в 3–4 предложения, с ключевыми сущностями, фактами и связью с предыдущими событиями; для этой связи в запрос добавляется пересказ прошлого фрагмента. Затем считается эмбеддинг **только пересказа** (`RAG2_EMBEDDING_MODEL`, через тот же ключ ProxyAPI), а вектор привязывается к исходному фрагменту.

При вопросе бот считает его вектор и сравнивает с векторами пересказов, а в запрос ответа отдаёт **исходный текст** найденных фрагментов. Сами пересказы в контекст ответа не попадают. Текст запроса пересказа — `SUMMARY_TASK` в [rag2.py](rag2.py); если поменяете его, увеличьте `PROMPT_VERSION`, иначе останутся старые пересказы.

**Поиск гибридный.** Как и в `rag.py` с эмбеддингами, результаты векторного поиска объединяются с поиском по словам в исходном тексте (RRF). Пересказ может потерять редкое имя или точную цитату, а поиск по словам найдёт их в оригинале. Так сохраняется то, что умел `/раг`. Векторы при этом никогда не считаются от исходного текста.

**Пока индекс строится.** Первая сборка занимает время, но бот отвечает как обычно: готовые фрагменты находятся по смыслу, остальные — пока только по словам. `/раг2` показывает прогресс. Обработка идёт по одному фрагменту с паузой `RAG2_SUMMARY_INTERVAL_SEC` (3 с), продолжается после перезапуска и не занимает дневной лимит бесед. При сбое API пауза растёт от 30 с до `RAG2_MAX_BACKOFF_SEC` (10 минут), ошибка видна в `/раг2`, фрагмент будет пересказан позже. Если API эмбеддингов недоступен при вопросе, работает поиск по словам. `RAG2_BUILD = False` выключает фоновую сборку.

**Стоимость.** На каждый фрагмент — один платный запрос к модели и один к эмбеддингам. Книга на 1,8 млн символов — примерно 1000 фрагментов и не меньше 50 минут при паузе 3 с плюс время самих запросов. Перед запуском на большой библиотеке оцените цену по тарифам вашего аккаунта. Пересказы кэшируются по тексту фрагмента в `rag2_index.db`: повторная индексация того же текста, смена модели эмбеддингов и перезапуск за них заново не платят. Пересказы удалённого текста остаются в этом кэше (в ответы не попадают); чтобы от них избавиться, удалите `rag2_index.db` — индекс соберётся заново, снова платно.

**Сочетание с /раг.** `/раг вкл` и `/раг2 вкл` заменяют друг друга: в беседе действует один режим. `/раг вкл`, `/раг выкл` и `/раг вопрос` по-прежнему работают только с папкой `RAG` и `rag_index.db`, а `/лимит чанков` действует на оба. Книги между папками не копируются автоматически: что положите в `RAG2`, то и будет в индексе 2. Исключение — рефлексия: «Имя, запомни» пишет `RAG/Рефлексия.txt` и такую же копию в `RAG2/Рефлексия.txt`, новые фрагменты пересказываются в фоне и до этого находятся по словам. Сбой записи копии не мешает основной записи — бот сообщит о нём в ответе.

Порог `RAG2_DENSE_MIN_SIM = 0.3` и модель эмбеддингов выбраны по описанию API и на настоящих книгах не откалиброваны; как их проверить — в [RAG_IDEAS.md](RAG_IDEAS.md#сравнить-раг2-с-раг).

## Интервал только для следующего вопроса

Перешлите **ровно два разных сообщения из этой же беседы** с подписью `/контекст`. Порядок пересылки не важен. Бот загрузит историю ВК страницами до ранней границы, включая пропуски локальной базы, и ответит служебным сообщением с датами и числом сообщений. Модель при выборе интервала не вызывается.

Следующее **обращение к боту** (слово «Имя», reply на сообщение бота, либо личное сообщение, если личка разрешена) получит все сообщения между этими датами включительно и сам новый вопрос. Сообщения с тем же временем до секунды тоже включаются. Нет ограничения в 500 сообщений и нет сжатия/обрезки выбранного текста. Служебные ответы бота и команды выбора контекста/внимания в историю модели не входят.

После этого обращения автоматически действует прежний контекст: стандартное окно последних сообщений либо ранее заданные `/контекст N` или `/автоконтекст`. Обычные сообщения без обращения и служебные команды интервал не расходуют. В очереди на паузе интервал закрепляется за одним следующим вопросом; вопросы до и после него остаются отдельными запросами с обычной историей. Неудачный ответ тоже расходует интервал. Выбор переживает перезапуск до поступления вопроса; очередь уже принятых вопросов, как и в bot7, хранится в памяти.

Пример: переслать сообщения от 10:00 и 11:00 с `/контекст`, дождаться подтверждения, написать «Имя, какие доводы привели участники?». История этого ответа — 10:00–11:00. Следующий вопрос снова использует обычную историю.

`/сброс контекста` отменяет ещё не использованный интервал; `/контекст N` заменяет выбор числом сообщений. При неверных границах, сообщении из чужой беседы или ошибке загрузки истории прежний выбор сохраняется. Если у пересланного сообщения нет `peer_id`, принадлежность проверяется по автору, времени, содержимому и `conversation_message_id`, когда он присутствует, в истории текущей беседы. Сообщения, недоступные боту в ВК, восстановить невозможно.

Старые варианты сохранены: `/контекст`, `/контекст 50`, `/контекст сброс`, `/автоконтекст` с одним пересланным сообщением или reply, `/автоконтекст 2 ч`, `/сброс контекста [N]`. Подробности обычного окна — в [bot7](../bot7/README.md#размер-контекста).

## Внимание

| Команда | Результат |
|---|---|
| `/внимание` + пересланные сообщения | Добавить их к закреплённому вниманию этой беседы; одинаковые пересылки не дублируются |
| `/внимание` | Показать служебным сообщением даты и авторов закреплённых сообщений, без запроса к модели |
| `/внимание сброс` | Удалить все закрепления в этой беседе |

В последующих обычных ответах модель получает **последний контекст + внимание + новый вопрос**. При разовом интервале последний контекст заменяется интервалом, а внимание сохраняется. Пересылки могут быть из другой беседы; сохраняются текст, дата, автор и картинки. Картинки передаются в рамках прежнего `MAX_IMAGES_PER_REQUEST`. Состояние хранится в SQLite, переживает перезапуск и не смешивается между беседами. В режиме `/раг вкл` внимание также передаётся модели вместе с историей и найденными фрагментами. Оно само не добавляется в книги RAG.

Текст внимания не исчезает из запроса после истечения временного лимита символов. `/забудь` начинает беседу с чистого листа, очищая также внимание и ещё не использованный интервал; сами записи истории остаются в базе.

## Временный лимит символов

После установки контекста (`/контекст N`, интервал, `/автоконтекст`) или добавления внимания бот считает объём истории и внимания. Если он превышает базовый `/лимит символов`, лимит автоматически поднимается на **60 секунд** (`AUTO_CHARS_SECONDS`). Ручная настройка не перезаписывается. Через минуту снова действует именно она, либо стандарт 12 000, если ручной настройки нет. Беседы независимы.

Чтение настроек и новые ответы не продлевают минуту. Пока она действует, объём истории при ответе пересчитывается без продления срока. Новая явная команда контекста/добавления внимания может запустить следующую минуту. `/лимит символов N` или `сброс` сразу отменяет временную надстройку. Обычный бюджет ограничен `MAX_CONTEXT_CHARS_CAP` (300 000), как ручной лимит; явно выбранный интервал и закреплённый текст передаются полностью и после истечения минуты. При превышении входного окна самой модели API может отказать: бот сообщает о неудачном ответе, а не выдаёт незаметно урезанный интервал за полный.

## Рефлексия

- **«Имя, запомни»** или `/запомни` + текст, пересылки или reply **дописывает** `RAG/Рефлексия.txt`.
- **«Имя, запомни с нуля»** или `/запомни с нуля` **заменяет** этот файл целиком.

Оба варианта по умолчанию доступны администратору (`REMEMBER_ADMIN_ONLY`). Пустой ввод не стирает файл. Запись атомарная, предыдущее содержимое сохраняется в `.bak`; файл переиндексируется, поэтому заменённые фрагменты больше не находятся. Длинный текст, разрезанный ВК, склеивается с сохранением выбранного режима. Файл общий для базы знаний этого экземпляра бота, как в bot7; его копия лежит в `RAG2` (см. [/раг2](#база-знаний-с-пересказами-раг2)).

## Команды в терминале

Запускайте `python bot9.py` в интерактивном терминале. Локальный оператор имеет права администратора. Команды используют те же обработчики и меняют настройки выбранной беседы:

```text
/чаты
/чат 2000000001
/помощь
/роль философ
/контекст 50
/автоконтекст 2 ч
/внимание
/внимание сброс
/запомни Новая мысль для рефлексии.
/запомни с нуля Новый текст рефлексии.
/раг вкл
/раг2 вкл
/лимит чанков 8
/рассуждения выкл
/лимит токенов 3000
/лимит символов 20000
/пересказ 20
/мысль
/пауза 2
/пауза 0
0
```

`/чаты` показывает известные `peer_id`; `/чат peer_id` выбирает беседу, даже если она ещё не появилась в истории. Если известна ровно одна беседа, она выбирается автоматически; иначе бот просит сделать выбор. Можно вводить остальные текстовые команды из `/помощь`, включая сброс роли, контекста и дневного лимита, разовые вопросы `/раг вопрос`, `/раг2 вопрос` и `/забудь`. Отправить пересылку или reply через терминал нельзя — соответствующие варианты остаются в чате.

**Результат терминальной команды выводится только в терминал** и не записывается как сообщение беседы. Это относится также к ответу LLM после паузы и уведомлению об истечении часового лимита токенов. Обращения из ВК продолжают получать ответы в ВК. Поток чтения stdin лишь ставит строки в очередь; SQLite и обработчики команд работают в главном потоке.

`0` + Enter или «Имя, стоп машина» в терминале останавливает бота. Из чата остановка по-прежнему доступна только администратору. Все остальные права чата сохранены. `--no-terminal` (также прежний `--no-terminal-stop`) отключает чтение stdin; `TERMINAL_STOP=False` действует так же. Под systemd без интерактивного stdin управление остаётся через чат.

## Запуск и переход с bot8

Из корня репозитория:

```bash
python3 -m venv .venv
.venv/bin/pip install -r Прочее/bot9/requirements.txt
.venv/bin/python Прочее/bot9/bot9.py --log-file Прочее/bot9/logs/bot9.log
# серверный режим: .venv/bin/python Прочее/bot9/bot9_server.py
```

Создайте `Прочее/bot9/.env` (образец — [.env.example](.env.example)):

```dotenv
VK_TOKEN=ключ_сообщества
VK_GROUP_ID=123456
PROXYAPI_KEY=ключ_ProxyAPI
ADMIN_IDS=123,456
# VK_USER_TOKEN=необязательный_ключ_для_постов
GROUP_NAME=грань
```

В сообществе включите Bots Long Poll, входящие и исходящие сообщения; дайте боту доступ ко всем сообщениям беседы. Без своего `.env` bot9 ищет его в текущей папке, затем `../bot8`, `../bot7`, `../bot6`, `../bot5`; без `GROUP_NAME` в старом файле действует значение `грань`. Для подробной трассировки — `--debug` или `BOT_DEBUG=1`; по умолчанию она выключена. В отладочном логе видны выбор/расход интервала, состав контекста и изменения временного лимита.

bot9 использует отдельную `gran9.db`. При первом запуске из `gran8.db` рядом с ботом, в текущей папке или `../bot8` (либо из явного `OLD_DB_PATH`) переносятся история, роли, имена, лимиты и режимы бесед. База bot8 не меняется; перенос отмечается в новой БД и не повторяется. Перед переходом остановите bot8, скопируйте нужные книги и `Рефлексия.txt` из `bot8/RAG` в `bot9/RAG`, нужные для `/раг2` книги — в `bot9/RAG2`, при необходимости перенесите свою `Роль.txt`. Индексы создадутся заново. Два бота с одним VK-токеном одновременно запускать не следует.

Для Ansible скопируйте [inventory.example.ini](ansible/inventory.example.ini) в `ansible/inventory.ini`, [secrets.example.yml](ansible/secrets.example.yml) в `ansible/secrets.yml`, заполните значения, зашифруйте секреты и запустите:

```bash
cd Прочее/bot9/ansible
ansible-vault encrypt secrets.yml
ansible-playbook -i inventory.ini playbook.yml -e @secrets.yml --ask-vault-pass
```

Плейбук поддерживает Debian/Ubuntu и RHEL/Fedora, локальное копирование или git, ставит службу `gran-bot9`. Настройки — в `vars` плейбука: название группы — `bot9_group_name`, книги — `bot9_rag_src` и `bot9_rag2_src`; детали серверного режима и его коды выхода сохранены из [bot7](../bot7/README.md#установка-на-чистый-сервер-ansible).

Проверка запускает все `experiments/test_*.py` в отдельных процессах (чтобы версии `rag`/`filosof` не смешивались), smoke главных циклов bot4–bot9, синтаксис Python/Ansible, базовый lint и ссылки Markdown. Полные логи каждого набора сохраняются отдельно. Workflow делает то же на Python 3.11 и 3.13; каждому набору отведено 120 секунд, задан предел времени задания CI.

[test_rag2_bot9.py](../../experiments/test_rag2_bot9.py) проверяет, что векторы считаются только от пересказов, вопрос без слов книги находит нужный пересказ, а наружу выходит исходный фрагмент; продолжение после перезапуска, кэш пересказов, удаление и замену книг, сбои API и изменение книги во время запроса. [test_bot9_new.py](../../experiments/test_bot9_new.py) проверяет `/раг2` и неизменность `/раг`, замену режимов, зеркало рефлексии, настоящий фоновый поток, другое название группы (включая запуск с настоящим файлом `.env`) и отсутствие имени «зашитого» в коде и настройках. [smoke_bot9_rag2_main.py](../../experiments/smoke_bot9_rag2_main.py) проходит сценарий через настоящие `init()/main()`. Унаследованные тесты проверяют остальные возможности bot8.

БЯМ, эмбеддинги и ВК в этих проверках подменены. На живом сообществе и платной модели проверки не запускались: настоящие запросы к эмбеддингам ProxyAPI (адрес и модель взяты из [документации](https://proxyapi.ru/docs/openai-embeddings)), качество пересказов и найденных фрагментов, порог сходства, реальные время и стоимость сборки, окна модели, доступ к истории ВК и управление systemd на удалённом сервере этими тестами не проверяются.
