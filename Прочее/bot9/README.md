# bot8 — бот «Грань» для ВКонтакте

Версия по [задаче #19](https://github.com/PavelChurkin/ai_mind_test1/issues/19), на базе [bot7](../bot7/README.md). Сохранены его команды, RAG с последовательной генерацией, рассуждения, роли, склейка длинных сообщений, картинки, паузы, лимиты, пересказы, `/мысль`, серверный запуск и Ansible. Старые папки ботов остаются самостоятельными версиями.

| Файл | Назначение |
|---|---|
| [bot8.py](bot8.py) | Бот, история SQLite, команды чата и терминала |
| [rag.py](rag.py) | Чтение книг, индекс, поиск и источники |
| [RAG_IDEAS.md](RAG_IDEAS.md) | Предложения по улучшению RAG и проверке качества |
| [bot8_server.py](bot8_server.py) | Серверный запуск с перезапуском раз в неделю |

| [filosof.py](filosof.py), [nouns.json](nouns.json), [verbs.json](verbs.json), [adject.json](adject.json) | Генератор `/мысль` |

## Интервал только для следующего вопроса

Перешлите **ровно два разных сообщения из этой же беседы** с подписью `/контекст`. Порядок пересылки не важен. Бот загрузит историю ВК страницами до ранней границы, включая пропуски локальной базы, и ответит служебным сообщением с датами и числом сообщений. Модель при выборе интервала не вызывается.

Следующее **обращение к боту** (слово «Грань», reply на сообщение бота, либо личное сообщение, если личка разрешена) получит все сообщения между этими датами включительно и сам новый вопрос. Сообщения с тем же временем до секунды тоже включаются. Нет ограничения в 500 сообщений и нет сжатия/обрезки выбранного текста. Служебные ответы бота и команды выбора контекста/внимания в историю модели не входят.

После этого обращения автоматически действует прежний контекст: стандартное окно последних сообщений либо ранее заданные `/контекст N` или `/автоконтекст`. Обычные сообщения без обращения и служебные команды интервал не расходуют. В очереди на паузе интервал закрепляется за одним следующим вопросом; вопросы до и после него остаются отдельными запросами с обычной историей. Неудачный ответ тоже расходует интервал. Выбор переживает перезапуск до поступления вопроса; очередь уже принятых вопросов, как и в bot7, хранится в памяти.

Пример: переслать сообщения от 10:00 и 11:00 с `/контекст`, дождаться подтверждения, написать «Грань, какие доводы привели участники?». История этого ответа — 10:00–11:00. Следующий вопрос снова использует обычную историю.

`/сброс контекста` отменяет ещё не использованный интервал; `/контекст N` заменяет выбор числом сообщений. При неверных границах, сообщении из чужой беседы или ошибке загрузки истории прежний выбор сохраняется. Если у пересланного сообщения нет `peer_id`, принадлежность проверяется по автору, времени, содержимому и `conversation_message_id`, когда он присутствует, в истории текущей беседы. Сообщения, недоступные боту в ВК, восстановить невозможно.

Старые варианты сохранены: `/контекст`, `/контекст 50`, `/контекст сброс`, `/автоконтекст` с одним пересланным сообщением или reply, `/автоконтекст 2 ч`, `/сброс контекста [N]`. Подробности обычного окна — в [bot7](../bot7/README.md#размер-контекста).

## Внимание

| Команда | Результат |
|---|---|
| `/внимание` + пересланные сообщения | Добавить их к закреплённому вниманию этой беседы; одинаковые пересылки не дублируются |
| `/внимание` | Показать служебным сообщением даты и авторов закреплённых сообщений, без запроса к модели |
| `/внимание сброс` | Удалить все закрепления в этой беседе |

В последующих обычных ответах модель получает **последний контекст + внимание + новый вопрос**. При разовом интервале последний контекст заменяется интервалом, а внимание сохраняется. Пересылки могут быть из другой беседы; сохраняются текст, дата, автор и картинки. Картинки передаются в рамках прежнего `MAX_IMAGES_PER_REQUEST`. Состояние хранится в SQLite, переживает перезапуск и не смешивается между беседами. В режиме `/раг вкл` внимание также передаётся модели вместе с историей и найденными фрагментами. Оно само не добавляется в книги RAG.

Текст внимания не исчезает из запроса после истечения временного лимита символов. `/забудь` начинает беседу с чистого листа, очищая также внимание и ещё не использованный интервал; сами записи истории остаются в базе.

## Временный лимит символов

После установки контекста (`/контекст N`, интервал, `/автоконтекст`) или добавления внимания бот считает объём истории и внимания. Если он превышает базовый `/лимит символов`, лимит автоматически поднимается на **60 секунд** (`AUTO_CHARS_SECONDS`). Ручная настройка не перезаписывается. Через минуту снова действует именно она, либо стандарт 12 000, если ручной настройки нет. Беседы независимы.

Чтение настроек и новые ответы не продлевают минуту. Пока она действует, объём истории при ответе пересчитывается без продления срока. Новая явная команда контекста/добавления внимания может запустить следующую минуту. `/лимит символов N` или `сброс` сразу отменяет временную надстройку. Обычный бюджет ограничен `MAX_CONTEXT_CHARS_CAP` (300 000), как ручной лимит; явно выбранный интервал и закреплённый текст передаются полностью и после истечения минуты. При превышении входного окна самой модели API может отказать: бот сообщает о неудачном ответе, а не выдаёт незаметно урезанный интервал за полный.

## Рефлексия

- **«Грань, запомни»** или `/запомни` + текст, пересылки или reply **дописывает** `RAG/Рефлексия.txt`.
- **«Грань, запомни с нуля»** или `/запомни с нуля` **заменяет** этот файл целиком.

Оба варианта по умолчанию доступны администратору (`REMEMBER_ADMIN_ONLY`). Пустой ввод не стирает файл. Запись атомарная, предыдущее содержимое сохраняется в `.bak`; файл переиндексируется, поэтому заменённые фрагменты больше не находятся. Длинный текст, разрезанный ВК, склеивается с сохранением выбранного режима. Файл общий для базы знаний этого экземпляра бота, как в bot7.

## Команды в терминале

Запускайте `python bot8.py` в интерактивном терминале. Локальный оператор имеет права администратора. Команды используют те же обработчики и меняют настройки выбранной беседы:

```text
/чаты
/чат 2000000001
/помощь
/роль философ
/контекст 50
/автоконтекст 2 ч
/внимание
/внимание сброс
/запомни Новая мысль для рефлексии.
/запомни с нуля Новый текст рефлексии.
/раг вкл
/лимит чанков 8
/рассуждения выкл
/лимит токенов 3000
/лимит символов 20000
/пересказ 20
/мысль
/пауза 2
/пауза 0
0
```

`/чаты` показывает известные `peer_id`; `/чат peer_id` выбирает беседу, даже если она ещё не появилась в истории. Если известна ровно одна беседа, она выбирается автоматически; иначе бот просит сделать выбор. Можно вводить остальные текстовые команды из `/помощь`, включая сброс роли, контекста и дневного лимита, разовый вопрос `/раг вопрос` и `/забудь`. Отправить пересылку или reply через терминал нельзя — соответствующие варианты остаются в чате.

**Результат терминальной команды выводится только в терминал** и не записывается как сообщение беседы. Это относится также к ответу LLM после паузы и уведомлению об истечении часового лимита токенов. Обращения из ВК продолжают получать ответы в ВК. Поток чтения stdin лишь ставит строки в очередь; SQLite и обработчики команд работают в главном потоке.

`0` + Enter или «Грань, стоп машина» в терминале останавливает бота. Из чата остановка по-прежнему доступна только администратору. Все остальные права чата сохранены. `--no-terminal` (также прежний `--no-terminal-stop`) отключает чтение stdin; `TERMINAL_STOP=False` действует так же. Под systemd без интерактивного stdin управление остаётся через чат.

## Запуск и переход с bot7

Из корня репозитория:

```bash
python3 -m venv .venv
.venv/bin/pip install -r Прочее/bot8/requirements.txt
.venv/bin/python Прочее/bot8/bot8.py --log-file Прочее/bot8/logs/bot8.log
# серверный режим: .venv/bin/python Прочее/bot8/bot8_server.py
```

Создайте `Прочее/bot8/.env`:

```dotenv
VK_TOKEN=ключ_сообщества
VK_GROUP_ID=123456
PROXYAPI_KEY=ключ_ProxyAPI
ADMIN_IDS=123,456
# VK_USER_TOKEN=необязательный_ключ_для_постов
```

В сообществе включите Bots Long Poll, входящие и исходящие сообщения; дайте боту доступ ко всем сообщениям беседы. Без своего `.env` bot8 ищет его в текущей папке, затем `../bot7`, `../bot6`, `../bot5`. Для подробной трассировки — `--debug` или `BOT_DEBUG=1`; по умолчанию она выключена. В отладочном логе видны выбор/расход интервала, состав контекста и изменения временного лимита.

bot8 использует отдельную `gran8.db`. При первом запуске из `gran7.db` рядом с ботом, в текущей папке или `../bot7` (либо из явного `OLD_DB_PATH`) переносятся история, роли, имена, лимиты и режимы бесед. База bot7 не меняется; перенос отмечается в новой БД и не повторяется. Перед переходом остановите bot7, скопируйте нужные книги и `Рефлексия.txt` из `bot7/RAG` в `bot8/RAG`, при необходимости перенесите свою `Роль.txt`. Индекс книг создастся заново. Два бота с одним VK-токеном одновременно запускать не следует.

Для Ansible скопируйте [inventory.example.ini](ansible/inventory.example.ini) в `ansible/inventory.ini`, [secrets.example.yml](ansible/secrets.example.yml) в `ansible/secrets.yml`, заполните значения, зашифруйте секреты и запустите:

```bash
cd Прочее/bot8/ansible
ansible-vault encrypt secrets.yml
ansible-playbook -i inventory.ini playbook.yml -e @secrets.yml --ask-vault-pass
```

Плейбук поддерживает Debian/Ubuntu и RHEL/Fedora, локальное копирование или git, ставит службу `gran-bot8`. Настройки — в `vars` плейбука; детали серверного режима и его коды выхода сохранены из [bot7](../bot7/README.md#установка-на-чистый-сервер-ansible).

## Проверка

Из корня репозитория:

```bash
python3 -m pip install -r Прочее/bot8/requirements.txt snowballstemmer ruff ansible-core
python3 experiments/check_bot8.py --logs /tmp/bot8-checks
# только новые сценарии задачи:
python3 -m unittest experiments/test_bot8_new.py -v
```

Проверка запускает все `experiments/test_*.py` в отдельных процессах (чтобы версии `rag`/`filosof` не смешивались), smoke главных циклов bot4–bot8, синтаксис Python/Ansible, базовый lint и ссылки Markdown. Полные логи каждого набора сохраняются отдельно. Новый workflow делает то же на Python 3.11 и 3.13; каждому набору отведено 120 секунд, задан предел времени задания CI.

Новые тесты сначала воспроизводили отсутствие функций bot8. Сейчас они проверяют границы и полноту интервала, очереди, ошибки, восстановление обычного контекста, точное истечение минуты, постоянство внимания, картинки, оба режима рефлексии и отсутствие вывода терминальных команд в ВК. Унаследованные тесты проверяют остальные возможности bot7; smoke запускает настоящий `init()/main()` с библиотеками VK/OpenAI, подменяя сетевые сервисы.

На живом сообществе и платной модели проверки не запускались; реальные окна модели, доступ к истории ВК, качество ответов и управление systemd на удалённом сервере этими тестами не проверяются.
