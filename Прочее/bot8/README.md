## База знаний: `/раг вкл` / `/раг выкл`

Режим включается для беседы и хранится в базе (переживает перезапуск). По умолчанию выключен (`RAG_MODE_DEFAULT`).

- **`/раг выкл`** — как раньше: бот отвечает только по истории сообщений беседы.
- **`/раг вкл`** — каждый ответ проходит **последовательную генерацию** (`rag_mode_answer`):
  1. по новым обращениям к боту (на которые он сейчас отвечает) ищутся фрагменты в базе знаний — не больше `/лимит чанков` штук;
  2. **нашлось** — модель получает историю беседы и пронумерованные фрагменты с указанием: отвечать **только по фрагментам, ничего не выдумывать**, ссылаться на номера `[1]`, а если ответа во фрагментах нет — ответить `НЕТ_ОТВЕТА`. Под ответом — «Источники: [1] «Книга», Глава 2»;
  3. **не нашлось** (или модель ответила `НЕТ_ОТВЕТА`) — второй запрос, обычный ответ по истории, и сообщение начинается со строки **«Поиск по базе знаний не дал результата.»**

  История нужна и в шаге 2: по ней модель понимает, о чём вопрос («а что он говорил про это?»), но факты берёт только из фрагментов. Строка «Поиск … не дал результата» и источники в историю для модели не попадают — иначе модель начинает подражать им.

Разовый вопрос к базе — как в bot6: **«Грань, РАГ вопрос»** или **`/раг вопрос`** — строго по книгам, а если ничего не нашлось — «⚙️ В базе знаний ничего не нашлось.» без запроса к модели. `/раг` без вопроса — что есть в базе. **`РАГ+` убран**: его задачу («книги, а если пусто — модель») теперь решает режим `/раг вкл`; «Грань, РАГ+ вопрос» понимается как «РАГ вопрос».

## `/лимит чанков` — «так же это делается?»

**Да, так и делается.** Книги в базе заранее разрезаны на фрагменты (чанки) по ~1000 символов (`rag.CHUNK_CHARS`, с перекрытием 200), поиск ранжирует их по близости к вопросу, и модели отдаются **k лучших** — это называется top-k, и подбор k — обычная настройка RAG-систем. Объём на входе модели ≈ k × 1000 символов: больше k — больше шансов, что ответ попадёт во фрагменты, но дороже запрос и больше постороннего текста, в котором модель может «потеряться»; меньше k — дешевле и точнее, но ответ может не попасть.

- **`/лимит чанков 10`** (админ) — передавать до 10 фрагментов (≈10 000 символов книг); `/лимит чанков` — показать; `/лимит чанков сброс` — к стандарту `RAG_TOP_K` = 6. Максимум — `RAG_TOP_K_MAX` = 30. Действует и на режим `/раг вкл`, и на разовые «РАГ вопрос».
- Фрагменты отбираются не только по количеству: подходят только те, где есть не меньше половины значимых слов вопроса (`RAG_MIN_COVERAGE`), поэтому при `/лимит чанков 20` модель получит 20 фрагментов, только если столько действительно подходит.
- Предохранитель — `RAG_MAX_CONTEXT_CHARS` = 40 000 символов: больше модели не уходит, сколько бы чанков ни было задано.

С чего начать: 4–8 чанков для коротких вопросов, 10–15 — для вопросов «расскажи всё про…». Если ответы «не находятся», хотя в книгах ответ есть, — поднимите лимит; если ответ уходит в сторону — опустите.

## `/мысль` без повтора и без увеличения лимита

Как и найдено в задаче, мысль не рождалась из-за промпта: с «не больше 100 слов» модель-«рассуждалка» обдумывала, как уложиться в сто слов, тратила на это весь лимит токенов и возвращала пустой ответ (`finish_reason=length`, «модель израсходовала весь лимит … на рассуждение»). В bot8:

- в [`filosof.py`](filosof.py) «не больше 100 слов» убрано из промптов образа и ответа, а в системный промпт добавлено «Пиши кратко»;
- у `/мысль` **нет повтора и нет увеличения лимита токенов** — три запроса цепочки идут со стандартным лимитом. Если ответ всё же пустой — «Мысль не родилась» с причиной, как раньше.

Повтор с `EMPTY_ANSWER_RETRY_TOKENS` остался только у обычных ответов в беседе.

## Рассуждения: `/рассуждения вкл` / `/рассуждения выкл`

По умолчанию выключены (`REASONING_DEFAULT = False`), режим хранится для каждой беседы.

- **`/рассуждения вкл`** — к запросу добавляется `{"thinking": {"type": "enabled"}}` (так DeepSeek включает режим рассуждения), а рассуждение, которое модель вернула (`reasoning_content` в ответе API), вставляется **в начало сообщения** между строками-маркерами:
  ```
  #рассуждения#
  Пользователь спрашивает о… Нужно вспомнить…
  #рассуждения#
  Сократ считал, что…
  ```
  Длинное рассуждение сокращается в середине (`REASONING_MAX_CHARS` = 6000 символов); если модель рассуждения не вернула — «(модель не вернула рассуждение)». В историю для модели блок рассуждения не попадает. Работает и с `/раг вкл`, и с `/мысль` (там рассуждения трёх шагов идут подряд).
- **`/рассуждения выкл`** — к запросу добавляется `{"thinking": {"type": "disabled"}}`: модель отвечает без рассуждения, и **весь лимит токенов уходит на ответ** — предупреждение «пустой ответ: модель израсходовала весь лимит (800 токенов) на рассуждение» из задачи в этом режиме не должно появляться.

Рассуждение тратит токены из `/лимит токенов`: при включённых рассуждениях может понадобиться поднять лимит (`/лимит токенов 3000`). Служебные запросы (сжатие истории) всегда идут без рассуждения.

**Не проверено на живом API:** передаёт ли ProxyAPI параметр `thinking` модели `deepseek-v4-flash` и возвращает ли `reasoning_content`. Поэтому: если API отвечает на параметр ошибкой 400/422, бот повторяет запрос без него, пишет об этом в лог и до конца работы параметр больше не передаёт (рассуждения тогда — как решит модель, показывается то, что она вернёт). Параметры можно поменять в настройках: `REASONING_ON_BODY`, `REASONING_OFF_BODY` (`None` — ничего не передавать). В строке лога каждого запроса видно, включены ли рассуждения и сколько символов рассуждения вернула модель.

## Размер контекста

Контекст — сколько последних сообщений беседы бот передаёт модели (стандарт `CONTEXT_SIZE` = 30). Служебные сообщения бота (с «⚙️») не считаются и не передаются.

| Команда | Что делает |
|---|---|
| `/контекст 50` | ручная подстройка: 50 последних сообщений (до `CONTEXT_SIZE_MAX` = 500). `/контекст` — показать, `/контекст сброс` — к стандарту |
| `/автоконтекст` + пересланное сообщение (или в ответ на него) | контекст **от этого сообщения до текущего** — число считается по истории. Работает, только если сообщение есть в истории этой беседы, иначе бот так и говорит. Переслано несколько — от самого раннего |
| `/автоконтекст 2 ч` | контекст — все сообщения **за последние 2 часа** (также `30 мин`, `1 д`, `1 нед`) |
| `/сброс контекста` | отменить автоконтекст и вернуться к заданному `/контекст` числу (или к стандарту) |
| `/сброс контекста 20` | то же, но сразу задать 20 |

Автоконтекст фиксирует **число** сообщений: с новыми сообщениями окно сдвигается, а не растёт. Если столько сообщений не влезает в лимит символов истории (`/лимит символов`), бот предупреждает: старая часть будет сжиматься в пересказ, как в bot6. Все значения хранятся в базе для каждой беседы.

**Отслеживание спора убрано**: в bot6 контекст сам рос, пока в беседе шёл спор, — в bot8 размер меняется только командами.

## Остановка

- **`0` и Enter в терминале**, где запущен бот, — остановка, как «Грань, стоп машина» (бот дописывает ответы, которые уже генерирует, и выходит с кодом 0). Под `bot8_server.py` бот читает терминал сервера, так что `0` работает и там; сервер после этого тоже завершается. Другой ввод — подсказка в лог. Выключить — `TERMINAL_STOP = False` или `--no-terminal-stop`. Если терминала нет (systemd, `nohup`, ввод из `/dev/null`), это просто не работает — останавливать через `systemctl stop gran-bot8`.
- **«Грань, стоп машина»** — **только для админов**: id из `ADMIN_IDS` в `.env` или админ беседы ВК (в личных сообщениях — только `ADMIN_IDS`). Остальным бот отвечает «⚙️ Остановить бота может только админ беседы.»

## Установка на чистый сервер (Ansible)

[`ansible/playbook.yml`](ansible/playbook.yml) ставит бота на сервер с Debian/Ubuntu (также RHEL/Rocky/Alma/Fedora), где ничего нет — даже python3: он ставится первым шагом через `raw`.

```bash
cd Прочее/bot8/ansible
cp inventory.example.ini inventory.ini            # адрес сервера, вход по SSH (root или sudo)
cp secrets.example.yml secrets.yml                # VK_GROUP_ID, VK_TOKEN, PROXYAPI_KEY, ADMIN_IDS
ansible-vault encrypt secrets.yml                 # по желанию: зашифровать токены
ansible-playbook -i inventory.ini playbook.yml -e @secrets.yml --ask-vault-pass
```

Что делает плейбук:

1. python3, sudo, acl (нужны самому Ansible), затем python3-venv, pip, git, сертификаты;
2. системный пользователь `gran` без входа в систему, папка `/opt/gran`;
3. код бота: по умолчанию — файлы из этой папки (`bot8_source: local`), или клон репозитория (`bot8_source: git`, `bot8_git_repo`, `bot8_git_version`);
4. виртуальное окружение `/opt/gran/venv` и `requirements.txt`;
5. `.env` с токенами (права 600, только для `gran`); книги базы знаний из `bot8_rag_src`, если задано;
6. служба systemd `gran-bot8`: `bot8_server.py` (перезапуск раз в `bot8_restart_days` суток с очисткой логов), после падения systemd поднимает бота снова (`Restart=on-failure`), «Грань, стоп машина» останавливает службу до `systemctl start gran-bot8`.

Повторный запуск плейбука обновляет код и зависимости и перезапускает бота; база `gran7.db`, индекс базы знаний и логи остаются. Управление:

```bash
systemctl status gran-bot8          # состояние
journalctl -u gran-bot8 -f          # вывод сервера
tail -f /opt/gran/bot8/logs/bot8.log
systemctl stop gran-bot8            # остановить (в терминале systemd «0» не ввести)
```

Остальные параметры (`bot8_timezone`, `bot8_debug`, `bot8_user`, `bot8_home` …) — в начале плейбука.

## Запуск

```bash
cd Прочее/bot8
pip install -r requirements.txt
python bot8.py                 # или python bot8_server.py; на сервере — ansible/
```

Файл `.env` — как у bot6 (`VK_TOKEN`, `VK_GROUP_ID`, `PROXYAPI_KEY`, `ADMIN_IDS`, `VK_USER_TOKEN`). Если рядом с bot8 его нет, бот берёт `.env` из текущей папки, затем из `../bot6`, затем из `../bot5`.

**Переход с bot6.** bot8 пишет в новую базу `gran7.db`. При первом запуске он переносит из `gran6.db` (рядом с ботом, в текущей папке или в `../bot6`; или путь из `OLD_DB_PATH`) историю, роли, имена, метки `/забудь`, лимиты и начало истории бесед. Перенос делается один раз. Книги базы знаний переложите в `bot8/RAG`.

## Что не проверено

На живом сообществе и живой модели bot8 не запускался. В частности:

- передаёт ли ProxyAPI параметр `thinking` модели `deepseek-v4-flash` и возвращает ли `reasoning_content` — от этого зависит, показываются ли рассуждения и отключаются ли они при `/рассуждения выкл` (если параметр отвергнут — бот работает без него, см. [выше](#рассуждения-рассуждения-вкл--рассуждения-выкл));
- что `/мысль` без «100 слов» рождается на живой модели — это наблюдение из задачи, в тестах модель подменена;
- запуск службы systemd: плейбук проверен на чистом контейнере ubuntu:24.04 (установка, повторный запуск без изменений, `systemd-analyze verify` юнита, запуск его `ExecStart` от пользователя `gran`), но systemd в контейнере не работает, поэтому `systemctl enable/start` на настоящем сервере с systemd не проверялись;
- качество ответов по базе знаний на больших книгах при разных `/лимит чанков`.
