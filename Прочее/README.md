# Прочее

Код, не связанный напрямую с древом состояний: чат-бот «Грань» для беседы сообщества ВКонтакте. Позже на базе чата группы планируется собрать бота с архитектурой мышления (см. [Архитектура мышления](../Архитектура%20мышления/README.md)). Папка создана по [задаче #11](https://github.com/PavelChurkin/ai_mind_test1/issues/11).

| Файл | Что это |
|------|---------|
| [`bot3.py`](bot3.py) | Исходная версия из задачи #11 (без изменений, только переводы строк приведены к LF) — для сравнения |
| [`bot4.py`](bot4.py) | Следующая версия: исправлен пустой контекст, добавлены reply, пересланные, картинки и посты |
| [`bot5/`](bot5/README.md) | Версия по [задаче #13](https://github.com/PavelChurkin/ai_mind_test1/issues/13): `/помощь`, `/пауза`, ответ сразу на несколько обращений, дневной лимит, `/лимит токенов` и `/лимит символов`, растущий в споре контекст со сжатием старой части, `/пересказ N от даты`, философская `/мысль`; описание и все настройки — в [bot5/README.md](bot5/README.md) |

## Почему в bot3 контекст оставался пустым

Найдено четыре причины; первая — главная.

1. **В беседах у сообщений бота `id = 0`.** Bots Long Poll в беседах отдаёт сообщения с `"id": 0`; уникален только `conversation_message_id` (в пределах беседы). В bot3 колонка `vk_msg_id` объявлена `UNIQUE`, а вставка идёт через `INSERT OR IGNORE`, поэтому **в каждой беседе сохранялось только первое сообщение, все следующие молча отбрасывались**. Это касается и первичной загрузки истории. Воспроизведение: [`experiments/bot3_context_bug.py`](../experiments/bot3_context_bug.py).
2. **Ответы бота не сохранялись.** `vk_send` отправлял сообщение, но не писал его в БД, а событие `message_reply` (исходящие сообщения) не обрабатывалось. Бот «не помнил», что сам говорил.
3. **Окно «последние 30 минут».** После получаса тишины контекст состоял из одного сообщения — того, на которое бот как раз отвечает, причём оно дублировалось в «ИСТОРИИ» и в «НОВОМ СООБЩЕНИИ». Кроме того, при большом потоке запрос `ORDER BY ts ASC LIMIT 30` брал **самые старые** 30 сообщений окна, а не самые новые.
4. **Сообщения без текста выпадали.** Фото, пересланные сообщения и репосты сохранялись с пустым `text` и пропускались при сборке контекста.

## Что изменилось в bot4

| Было (bot3) | Стало (bot4) |
|---|---|
| Уникальность по `id` | Уникальность по `(peer_id, conversation_message_id)` и по `(peer_id, id)` для `id > 0` |
| Ответ бота не сохраняется | Сохраняется сразу после отправки (`peer_ids` возвращает `conversation_message_id`), событие `message_reply` не создаёт дубль |
| Контекст — сообщения за 30 минут | Последние `CONTEXT_SIZE` (40) сообщений за `CONTEXT_MEMORY_HOURS` (12 ч), но **не меньше** `CONTEXT_MIN_MESSAGES` (10) последних, даже если они старые; ограничение `MAX_CONTEXT_CHARS` |
| Новое сообщение дублируется в истории | Исключается из истории |
| `reply_to` (в беседах у бота не работает) | В беседах — параметр `forward` с `conversation_message_ids` и `is_reply: 1`; в личке — `reply_to` |
| Отвечает только на слово «грань» | Ещё и на **reply к сообщению бота** и (настраивается `RESPOND_IN_PRIVATE`) на любые сообщения в личке |
| Пересланные — только для «перескажи», один уровень | Текст пересланных (с вложенностью до `FWD_MAX_DEPTH`) хранится в истории и виден модели |
| Картинки игнорируются | Фото из сообщения, reply, пересланных, постов и последних сообщений истории (до `MAX_IMAGES_PER_REQUEST`) передаются vision-модели; если модель не приняла картинки — повтор без них |
| Посты игнорируются | Текст поста, которым поделились, репосты (`copy_history`) и фото поста попадают в контекст; «грань, перескажи» работает и для постов |
| — | Пометки вложений: `[фото]`, `[стикер]`, `[голосовое: «расшифровка»]`, `[видео: …]`, `[ссылка: …]`, `[опрос: …]` |
| Имена только пользователей | Имена пользователей и сообществ (`groups.getById`), пакетно |
| История грузится один раз | При каждом старте догружаются последние `SYNC_ON_START` сообщений — то, что пришло, пока бот был выключен |
| — | `/забудь` — начать контекст беседы с чистого листа (история в БД остаётся) |
| — | Не чаще одного запроса к LLM за `LLM_MIN_INTERVAL_SEC`; длинные ответы режутся на части по 4000 символов |
| ВК, LLM и БД создаются при импорте | Создаются в `init()` — модуль можно тестировать без токенов |

Команды остались прежними: `Грань, стоп машина`, `/роль (…)`, `/пересказ N`, `Грань, перескажи` / `Грань, о чём тут` (в ответ на сообщение, с пересланными или с постом).

## Запуск

```bash
pip install vk_api openai python-dotenv
python bot4.py
```

Файл `.env` рядом с ботом:

```
VK_TOKEN=ключ доступа сообщества (права: сообщения)
VK_GROUP_ID=id сообщества без минуса
PROXYAPI_KEY=ключ ProxyAPI
# необязательно: ключ пользователя или сервисный ключ приложения —
# нужен, только если во вложении-посте нет текста (wall.getById не работает с ключом сообщества)
VK_USER_TOKEN=
```

В настройках сообщества: Long Poll API включён, события «Входящее сообщение» и «Исходящее сообщение» отмечены, у бота есть доступ ко всем сообщениям беседы (иначе он видит только обращения к себе).

**Переход с bot3.** bot4 пишет в новую базу `gran4.db`. При первом запуске он переносит из `gran.db` роли и имена, а историю заново загружает из ВК (в старой базе она неполная из-за бага с `id = 0`).

**Картинки.** По умолчанию (`IMAGE_MODE = "base64"`) бот скачивает фото и передаёт модели данными: так не важно, может ли сервер модели скачать картинку с серверов ВК. При `IMAGE_MODE = "url"` передаётся ссылка.

## Что не проверено

Проверки выше работают с подменёнными ВК и LLM: на живом сообществе и живой модели bot4 не запускался. В частности, не проверено на практике, принимает ли `deepseek/deepseek-v4-flash-vision-exp` через ProxyAPI картинки в формате `image_url` (на этот случай есть повтор без картинок).
