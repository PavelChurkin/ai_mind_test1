# bot5 — бот «Грань» для беседы сообщества ВКонтакте

Следующая версия [`bot4.py`](../bot4.py), сделана по [задаче #13](https://github.com/PavelChurkin/ai_mind_test1/issues/13). Всё, что умел bot4 (история в SQLite, reply, пересланные, посты, картинки для vision-модели, `/роль`, `/забудь`, «Грань, перескажи»), осталось. Что добавлено — ниже.

|------|---------|

## Базовый функционал

**Когда бот отвечает.** В беседе — на сообщения со словом «грань», на reply к своему сообщению и на команды. В личных сообщениях — только если `ALLOW_PRIVATE_MESSAGES = True` (по умолчанию нет: личные сообщения сохраняются, но бот молчит); тогда отвечает на любое сообщение.

**Ответ сразу на всех.** Бот не отвечает мгновенно: он ждёт `BATCH_WAIT_SEC` (8 с) и, если за это время к нему никто больше не обратился, отвечает **одним сообщением на все** накопившиеся обращения, называя авторов по имени. Так он видит полный контекст, а запросов к модели меньше. Чтобы бот не молчал вечно, когда обращения идут непрерывно, через `BATCH_MAX_WAIT_SEC` (60 с) после первого обращения он отвечает в любом случае.

**Пауза.** `/пауза` — бот минуту (`PAUSE_DEFAULT_MINUTES`) не отвечает, а копит обращения и команды, которым нужна модель (`/пересказ`, `/мысль`, «Грань, перескажи»). Когда пауза кончилась — выполняет команды по порядку и одним сообщением отвечает на все обращения. Служебные команды (`/помощь`, `/лимит …`, `/пауза 0` и т. п.) работают и на паузе. Очередь хранится в памяти: если бота перезапустить во время паузы, накопленные обращения пропадут (сами сообщения останутся в истории).

**Контекст растёт в споре.** Обычно модель видит `CONTEXT_SIZE` (30) последних сообщений. Если промежутки между ответами бота сокращаются (разгорается спор), контекст начинает расти на 1 с каждым новым сообщением в беседе (до `CONTEXT_SIZE_MAX`), так что бот не теряет начало спора. Если `CONTEXT_RESET_MINUTES` (5 мин) в беседе не было новых сообщений — контекст снова `CONTEXT_SIZE`.

**Контекст не упирается в лимит символов.** Сколько символов истории передавать модели, ограничивает `MAX_CONTEXT_CHARS` (в беседе меняется командой `/лимит символов`). Раньше (bot4) всё, что не влезало, просто выбрасывалось — в долгом споре бот забывал его начало. Теперь старая часть истории **сжимается в краткий пересказ** (до `CONTEXT_SUMMARY_CHARS` символов), а свежие сообщения идут дословно. Пересказ сохраняется в БД и дополняется только тогда, когда свежая часть снова перестала помещаться (свежей части после сжатия отводится `CONTEXT_KEEP_SHARE` места — с запасом), поэтому лишний запрос к модели бывает редко. Если сжать не удалось — старые сообщения обрезаются, как в bot4. Сообщения, на которые бот отвечает сейчас, передаются **всегда целиком** и в лимит не входят: большой объём можно отправить за раз.

**Длинные ответы.** ВК не принимает сообщения длиннее 4096 символов, поэтому ответ режется на части по `VK_MESSAGE_LIMIT` (4000): по абзацам, иначе по пробелам. Это было и в bot4; в bot5 добавлен тест.

**Дневной лимит.** Не больше `DAILY_MESSAGE_LIMIT` (100) ответов бота в сутки — по умолчанию у каждой беседы свой счётчик (`DAILY_LIMIT_PER_CHAT`). Ответом считается всё, что сгенерировала модель: ответ на обращения, пересказ, мысль (мысль — один ответ, хотя запросов к модели три). Служебные сообщения и сжатие контекста не считаются. При 25 %, 50 %, 90 % и 100 % лимита бот пишет в беседу служебное сообщение (если пороги совпали — например, при лимите 4 и 90 %, и 100 % — это 4, — одно, о старшем). На 100 % бот перестаёт обращаться к модели и на любые обращения отвечает «Извините, сегодня лимит сообщений достигнут.». Сутки начинаются в `LIMIT_RESET_HOUR` (0:00 по времени сервера) — тогда лимит сбрасывается; админ может сбросить его раньше командой `/сбросить лимит сообщений`.

**Лимит токенов ответа.** `/лимит токенов 30000` — ответы (и пересказы) могут быть длиннее. `/лимит токенов сброс` — снова стандарт `MAX_TOKENS_DEFAULT` (800). Чтобы большой лимит не остался включённым случайно, через `TOKEN_LIMIT_RESET_MINUTES` (60 мин) он сам возвращается к стандарту (0 — не возвращается).

**Пересказ с даты.** `/пересказ 100 от 12:00 16.10.2026` — пересказ 100 сообщений начиная с этого времени. Если таких старых сообщений в БД нет, бот догружает историю из ВК (`messages.getHistory`, от новых к старым) до нужной даты, но не больше `HISTORY_LOAD_MAX` сообщений. Если дата раньше создания беседы — эта часть игнорируется: пересказ начинается с первого сообщения, и в заголовке сказано, с какого времени в чате есть сообщения; начало беседы запоминается, второй раз история не грузится.

**Философская мысль.** `/мысль` — случайная мысль, `/мысль подробно` — вся цепочка её рождения. Алгоритм и промпты — из [ai_filosof](https://github.com/PavelChurkin/ai_filosof) (`ThoughtGenerator`): из словарей берётся большая случайная выборка, из неё — по 3 самых частых и по 2 «редких» существительных, глагола и прилагательных; по ним модель строит образ и выбирает себе роль, по образу формулирует вопрос, отвечает на него. Каждый шаг — отдельный запрос к модели. Модуль `filosof.py` ничего не знает про ВК и OpenAI — функцию запроса к модели ему передаёт бот. Словари (≈2,4 МБ) загружаются при первой мысли.

**Служебные сообщения** (помощь, лимиты, пауза, отказ в правах) начинаются с «⚙️» и не попадают в контекст модели.

## Команды

Тот же список выдаёт `/помощь` — вместе с текущими настройками беседы.

| Команда | Кто может | Что делает |
|---|---|---|
| «Грань, …» или reply на сообщение бота | все | ответ бота (через `BATCH_WAIT_SEC`, один на все обращения) |
| «Грань, перескажи» / «Грань, о чём тут» (в ответ на сообщение, с пересланными или с постом) | все | пересказ этого сообщения, пересланных или поста |
| `/пересказ N` | все; N > 100 — админ | пересказ последних N сообщений (без N — 100) |
| `/пересказ N от ЧЧ:ММ ДД.ММ.ГГГГ` | все; N > 100 — админ | пересказ N сообщений начиная с даты; можно «с» вместо «от»; дата и время в любом порядке; без года — этот год (если дата ещё не наступила — прошлый); только время — сегодня (или вчера) |
| `/мысль` | все | случайная философская мысль |
| `/мысль подробно` | все | мысль со всей цепочкой: слова → образ и роль → вопрос → ответ |
| `/пауза [минуты]` | все | не отвечать 1 мин (или N, до `PAUSE_MAX_MINUTES`), потом ответить на всё накопившееся; `/пауза 0` — снять паузу |
| `/забудь` | все | начать контекст с чистого листа (история в БД остаётся) |
| `/роль (текст)` | все | задать боту роль в этой беседе |
| `/помощь` | все | список команд и текущие настройки беседы |
| `/лимит токенов N` | админ | лимит длины ответа; `сброс` или `стандарт` — вернуть 800; без числа — показать |
| `/лимит символов N` | админ | лимит символов истории в запросе; `сброс` или `стандарт` — вернуть `MAX_CONTEXT_CHARS`; без числа — показать |
| `/сбросить лимит сообщений` | админ | обнулить дневной лимит |
| «Грань, стоп машина» | все | остановить бота (как в bot4) |

**Кто админ.** В личных сообщениях собеседник — админ своего чата: ему доступны все команды. В беседе админ — это админ или создатель беседы (бот узнаёт их через `messages.getConversationMembers`, для этого у бота должны быть права администратора беседы; список запоминается на `ADMIN_CACHE_MINUTES`), а также пользователи из `ADMIN_IDS` в `.env`. Если ВК не отдал список участников, админами считаются только `ADMIN_IDS`.

Настройки беседы (`/лимит токенов`, `/лимит символов`, дневной счётчик) хранятся в БД и переживают перезапуск.

## Ответы на вопросы из задачи

**Зачем был `POST_MAX_CHARS`?** В bot4 текст поста, которым поделились, обрезался до 4000 символов, чтобы один длинный пост не занял весь контекст. Раз нужен весь пост — в bot5 эта настройка убрана, пост сохраняется и передаётся модели целиком. Не помещается в историю — его вместе с остальной старой частью сожмёт пересказ (см. выше), а если пост в новом сообщении — он идёт целиком всегда.

**Что за `QUOTE_MAX_CHARS` и что за цитаты?** Когда пишут ответом (reply) на чьё-то сообщение, бот сохраняет в истории пометку, на что это ответ: `(в ответ Ивану: «…»)`. Внутри пометки — цитата исходного сообщения. Само исходное сообщение обычно уже есть в истории целиком, поэтому повторять его полностью в каждом ответе на него незачем — это только тратит место в контексте. `QUOTE_MAX_CHARS` — длина этой цитаты (в bot5 — 300 символов, 0 — без обрезки). Для «Грань, перескажи» цитата не обрезается: там берётся всё сообщение.

**Что за `MAX_CONTEXT_CHARS`?** Ограничение длины истории (в символах), которая уходит модели в одном запросе. Нужно, чтобы запрос не превысил окно модели и не стоил слишком дорого: сообщения бывают огромными (пересланные цепочки, посты). Ограничивает только историю: новые сообщения, на которые бот отвечает, передаются целиком. Для большого объёма админ ставит `/лимит символов 20000` (или больше). А чтобы растущий в споре контекст не упирался в лимит и бот не терял начало спора, то, что не помещается, сжимается в пересказ.

**Что за `CONTEXT_MEMORY_HOURS`?** «Срок давности» контекста. Если в беседе давно молчали, а потом кто-то обратился к боту, разговор, скорее всего, новый — и сообщения недельной давности ему только мешают. Поэтому сообщения старше `CONTEXT_MEMORY_HOURS` (12 ч) в контекст не берутся — кроме `CONTEXT_MIN_MESSAGES` (10) последних: их бот видит всегда, чтобы после тишины контекст не оказался пустым. 0 — без ограничения по времени.

## Запуск

```bash
pip install vk_api openai python-dotenv
cd Прочее/bot5
python bot5.py
```

Файл `.env` рядом с ботом:

```
VK_TOKEN=ключ доступа сообщества (права: сообщения)
VK_GROUP_ID=id сообщества без минуса
PROXYAPI_KEY=ключ ProxyAPI
# необязательно: id пользователей ВК, которые админы бота во всех беседах (через запятую)
ADMIN_IDS=
# необязательно: ключ пользователя или сервисный ключ приложения —
# нужен, только если во вложении-посте нет текста (wall.getById не работает с ключом сообщества)
VK_USER_TOKEN=
```

В настройках сообщества: Long Poll API включён, события «Входящее сообщение» и «Исходящее сообщение» отмечены, у бота есть доступ ко всем сообщениям беседы. Чтобы бот узнавал админов беседы, дайте ему в беседе права администратора (иначе используйте `ADMIN_IDS`).

**Переход с bot4.** bot5 пишет в новую базу `gran5.db`. При первом запуске он переносит из `gran4.db` (если она лежит рядом) историю сообщений, роли, имена и метки `/забудь` — схема та же, загружать историю из ВК заново не нужно.

## Проверка

```bash
python3 -m unittest experiments/test_bot5.py -v      # тесты, ВК и LLM подменены, время управляемое
python3 experiments/smoke_bot5_main.py               # main() с настоящими vk_api/openai без сети
```

## Что не проверено

Проверки выше работают с подменёнными ВК и LLM: на живом сообществе и живой модели bot5 не запускался. В частности, не проверено на практике:

- что `messages.getConversationMembers` с ключом сообщества отдаёт `is_admin`/`is_owner` (по документации ВК — да, если бот администратор беседы);
- что `messages.getHistory` для бота отдаёт старую историю беседы целиком (для пересказа с даты);
- как модель справляется с ответом сразу на несколько обращений и со сжатием истории.
